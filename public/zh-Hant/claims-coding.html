理賠申請與編碼參考資料

一份實用指南，說明美國政府及私人健康保險中，醫療理賠申請如何建立結構、編碼、提交及處理。

概覽

醫療理賠申請代表醫療服務提供者（醫師、醫院、化驗室、藥局或其他供應商）向付款方（保險計劃或政府計劃）提出的付款請求。理賠申請記錄了提供了什麼服務、為誰提供、由誰提供、原因（診斷）以及費用為何。正確的編碼與提交，對於及時付款及遵守計劃規定至關重要。

本參考資料說明了規範 Medicare、Medicaid、Medicare Advantage 與醫療保險市場理賠申請的表格、代碼集、標準及工作流程。此流程受到嚴格規範及標準化——任何偏差都可能導致理賠拒絕、延遲，或追討多付款項。

理賠申請表格與提交方式

專業理賠申請（CMS-1500）

CMS-1500表格是用於診所醫師服務、門診手術、診斷及其他專業服務的標準紙本理賠申請。雖然紙本理賠申請現已罕見，但 CMS-1500 的結構仍是電子專業理賠申請的基礎。它記載了：

  • 病人的基本資料與保險資訊
  • 醫療服務提供者與計費提供者的詳細資料（NPI、分類代碼）
  • 服務日期、服務地點（POS）及程序代碼（CPT/HCPCS）
  • 診斷代碼（ICD-10-CM）及病況指標
  • 修飾符（描述影響編碼或報銷的情況）
  • 費用與服務單位

機構理賠申請（UB-04 與 837I）

UB-04（或 CMS-1450）是用於醫院住院及門診、專業護理機構（SNF）與復健服務的紙本理賠申請表格。其電子版本為837I（機構）交易。主要欄位包括：

  • 入院及出院日期
  • 入院及出院狀態（例如：一般、轉院、居家照護）
  • 收入代碼（用於各部門或服務項目）
  • 病況代碼、事件代碼及價值代碼
  • 診斷代碼（ICD-10-CM）及程序代碼（ICD-10-PCS）
  • 按收入中心分類的費用

牙科與藥局理賠申請

牙科理賠申請使用 CDT（牙科程序及命名代碼）代碼，通常採用簡化格式。藥局理賠申請通常在藥局收銀台透過 POS（銷售點）系統以電子方式即時提交，並使用國家藥物代碼（NDC）。這些流程與專業及機構理賠申請路徑是分開的。

代碼集及其用途

代碼集 是什麼 用於
ICD-10-CM 國際疾病分類第10版臨床修訂版。約有70,000個診斷代碼。 記錄病人的病況、症狀及就診原因。所有理賠申請都必須提供。主要診斷與醫療必需性相關聯。次要診斷則說明併發症或合併症。
CPT 現行程序術語（由美國醫學會AMA擁有）。約有10,000個代碼，用於診所/門診環境中的程序、服務及諮詢。 專業理賠申請。描述執行了什麼服務。每年（1月）修訂一次。
HCPCS 第二級 醫療保健常用程序編碼系統。約有3,000個英數混合代碼（前綴字母如 J、E、G、K 等），用於耐用醫療設備、用品及CPT未涵蓋的服務。 專業理賠申請。涵蓋耐用醫療設備（輪椅、氧氣）、矯形器、特定藥物，以及CMS認定為非標準的服務。
ICD-10-PCS ICD-10程序編碼系統。約有72,000個程序代碼，僅用於機構（住院）環境。 僅用於機構理賠申請。描述住院期間所執行的程序及手術。
收入代碼 四位數代碼（例如：0100 = 房間及膳食；0340 = 物理治療），用於機構理賠申請中按服務項目整理費用。 UB-04/837I 理賠申請必須提供。將費用分組，以便集中審查與定價。
NDC（國家藥物代碼） 11位數識別碼，用於識別每種藥物的配方、劑量及包裝規格。 藥局理賠申請，以及當藥物作為用品或投藥服務計費時（例如輸液中心），機構/專業理賠申請上的用藥清單。
服務地點（POS） 兩位數代碼，表示服務提供的地點（例如：11 = 診所；21 = 住院醫院；57 = 門診手術中心）。 專業理賠申請。影響編碼規則、計費權限及報銷金額。
修飾符 附加於程序代碼後的英文字母或數字後綴（例如：-25 = 獨立服務；-59 = 不同的服務；-RT = 右側；-LT = 左側）。 專業理賠申請。說明會改變合併計費、計費規則或報銷方式的情況（例如同一天進行的檢查與程序）。

電子交易與標準

如今大多數理賠申請都是透過清算所以電子方式提交，並使用 HIPAA 及CMS制定的標準交易格式：

理賠與付款交易

  • 837-P（專業）——CMS-1500的電子版本。包含診斷、程序、修飾符及費用資料。
  • 837-I（機構）——UB-04的電子版本。包含收入代碼、病況代碼及住院專用欄位。
  • 837-D（牙科）——用於牙科及矯正理賠申請。
  • 835（ERA——電子匯款通知）——付款方的回覆；顯示每項理賠申請項目被允許、支付、拒絕或提出上訴的情況。與福利說明（EOB）相關聯。

資格與狀態交易

  • 270/271——即時資格查詢（270）及回覆（271）。用於服務前或當下，確認病人的承保範圍、共付額、自付額及自付狀況。
  • 276/277——理賠申請狀態查詢（276）及回覆（277）。用於追蹤待處理理賠申請的裁決進度。

清算所

清算所是一種廠商，負責接收醫療服務提供者的理賠申請，依CMS及各付款方的規定進行驗證，將其轉換為標準的HIPAA格式，並轉交給正確的付款方。清算所也會將匯款資訊送回醫療服務提供者。它們確保理賠申請在送達付款方之前符合技術標準，減少因格式錯誤而遭拒絕的情況。

無誤理賠申請的生命週期

  1. 驗證與預先授權——醫療服務提供者查核病人資格（270/271），並在需要時提交預先授權申請。此步驟確認該服務有承保，並確立醫療必需性。詳情請見醫療服務提供者與計費及健康計劃營運。
  2. 服務提供與文件記錄——醫療服務提供者提供服務，並在病歷中記錄，包括診斷（原因）、程序（內容）、日期、時間、提供者及服務地點。
  3. 編碼——醫療編碼員將文件記錄轉換為ICD-10-CM（診斷）及CPT/HCPCS（程序）代碼，視需要加上修飾符，並指定服務地點及計費提供者。
  4. 理賠申請整合與驗證——計費系統整合出837-P或837-I，進行內部檢查（診斷與程序是否關聯、修飾符是否適當、費用是否合理），並提交給清算所或直接提交給付款方。
  5. 清算所驗證——清算所檢查是否符合HIPAA規定、必填欄位及付款方特定的審核規則。拒絕無效的理賠申請，或將有效的理賠申請轉交給付款方。
  6. 付款方裁決——付款方系統查核服務當時的資格、套用病人的福利計劃、驗證是否符合預先授權規定、檢查是否重複或有詐欺跡象，並確定允許額。規則因計劃（Medicare、Medicaid、Medicare Advantage、醫療保險市場）而異。
  7. 付款與匯款——付款方支付醫療服務提供者（支票或電子轉帳）、拒絕理賠申請，或要求提供更多資訊。匯款資訊（835/ERA）會傳送給醫療服務提供者及清算所。
  8. 入帳與應收帳款——醫療服務提供者的計費人員將付款過帳到病人帳戶、確認收入，並更新帳齡報告。
  9. 病人計費——醫療服務提供者就任何剩餘餘額（共付額、共同保險、自付額，或未承保服務）向病人收費。

常見理賠拒絕原因

理賠申請因許多原因而遭拒絕或減額。常見情況包括：

  • 資格問題——病人在服務當日未有效註冊，或因未繳費而承保被暫停。
  • 缺少預先授權——該服務需要事先核准，但未取得，或已過期。
  • 編碼錯誤——診斷代碼無法支持該程序（缺乏醫療必需性），或程序代碼與服務地點連結錯誤。
  • 逾期提交違規——理賠申請在截止日期後提交（Medicare通常為180天；各州Medicaid計劃規定不一）。
  • 重複理賠申請——同一服務日期及代碼的理賠申請已經支付或正在處理中。
  • 福利協調（COB）——病人有其他保險，但未正確處理主要付款方的回覆。
  • 未承保服務——該服務在病人的計劃下被排除，或不屬於該計劃下的承保福利。
  • 醫療服務提供者網絡狀態——醫療服務提供者在服務當時不屬於網絡內，或網絡合約已終止。
  • 資訊缺失或無效——必填欄位（NPI、服務地點、修飾符或病人身分資料）不完整或無效。

被拒絕的理賠申請通常可以提出上訴，特別是當拒絕理由是基於醫療政策或文件記錄時。上訴流程及時限請見上訴時限。

與預先授權及會員上訴的關聯

理賠申請並非孤立存在。通常需要預先授權（在提供服務前先取得核准），而理賠申請必須參照該授權號碼，以避免遭拒絕。若理賠申請被拒絕，病人有權提出上訴。承保決定可基於醫療政策的分歧、付款錯誤，或資格判定錯誤而提出上訴——流程及時限因計劃而異。

  • 醫療服務提供者與計費——預先授權流程與規定
  • 健康計劃營運——計劃如何審核並支付理賠申請
  • 上訴時限——會員與醫療服務提供者的上訴權利及截止日期

重點摘要

  • 理賠申請是結構化、標準化的文件，會依循固定的工作流程，從醫療服務提供者經清算所送達付款方，最終完成付款。
  • 編碼準確性（ICD-10-CM、CPT、HCPCS、修飾符）及必填欄位的完整性，對避免理賠拒絕及延遲至關重要。
  • 透過HIPAA標準格式（837-P、837-I、835）進行電子提交，可確保一致性，並支援自動化裁決。
  • 預先授權、資格驗證及上訴，皆與理賠申請流程相互關聯。
  • 付款方在裁決時會套用各計劃特定的規則（Medicare、Medicaid、Medicare Advantage、醫療保險市場）；同一種理賠申請格式，並不代表適用同一套裁決規則。
請以官方資訊為準。本頁說明的是理賠申請與編碼的理論運作方式。實際規則、時限及上訴程序，會因付款方、州別（Medicaid而言）及計劃而異。請查閱您的付款方計費說明、醫療服務提供者手冊及HIPAA理賠申請提交標準，以取得最新規定。如有法規相關疑問，請參閱CMS.gov及官方計劃指南。
